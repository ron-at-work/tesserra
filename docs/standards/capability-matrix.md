## Required non-equivalence rules

The matrix relies on these hard boundaries:

- `spiffe://trust-domain/workload` **is not** a logical agent ID, OAuth client ID, human/service authority, or model identity.
- OAuth/OIDC `sub`, `client_id`, `act`, `may_act`, `aud`, and `scope` retain issuer- and protocol-specific meanings. They must not be silently converted to any ATTEST principal type.
- An A2A Agent Card is discovery/capability metadata. A signature on it establishes the selected card-signing claim under its verification policy; it does not authorize a live task or establish a runtime's identity.
- A model label/version is a provenance assertion. It confers no authority and does not prove which model generated a result without additional execution evidence.
- A signature validates bytes/key control under a selected trust policy. It does not prove signer honesty, safe behavior, correct execution, consent, or authorization.

## Why the ATTEST-defined rows are narrow

The **Define in ATTEST** rows are not attempts to standardize another identity, OAuth, or agent protocol. They are the minimum project semantics needed to make a verifier answer a bounded question: _given pre-validated external evidence and configured local trust, did a typed authority delegate a strictly bounded action to this logical agent for this task/resource/audience, and is the asserted runtime/provenance evidence linked to the request?_ The frozen project RFC makes every field trace to one of these gaps, including snapshot pinning, root ceilings, bounded chains, and canonical request/task-context digests.
